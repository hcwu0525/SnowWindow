## 如何理解记录中的状态

- **已核对**：有本地文件、代码或具体版本文档作为依据。
- **已运行**：已有运行产物；需同时注明验证范围和版本。
- **已实现、待验证**：存在代码或配置，但尚无对应完整实验的验证记录。
- **分析建议**：由现有证据提出的研究或接入方案，尚未证明优于现有方案。
- **待核实**：来源、单位、定义或适用性不充分，不能直接作为模型事实。

模型理论能力、软件版本实现、SnowWindow 适配器支持范围、某次实验结果，
是四个不同层次。更新时分别说明，避免把示例运行成功写成 G2F 验证通过。

## 持续维护约定

1. 数据清单与理论比较维护“当前认识”；使用日志追加带日期的历史记录。
2. 每次记录注明模型版本、配置、数据来源/指纹、训练与评估划分、
   产物位置、失败记录和结论适用范围。可复制[日志模板](model-usage-log.md#记录模板)。
3. 结论变化时说明替代了哪条旧结论及原因，保留历史实验依据。
4. 增加模型时，补充相同维度的机制、输入、输出、缺口和使用记录；
   内容较多时新建 `docs/models/<model>.md` 并在本页链接。
5. `data/` 保持只读。生成的表格、缓存、图、清单和实验报告放在
   `outputs/experiments/<experiment_id>/`；本目录只维护说明与索引。
6. 不用评估年份观测选择参数；不把失败或未成熟运行改写为成熟；
   全年播期情景不能当作全年播期实测验证。

`outputs/`、`.tools/` 和本地数据可能未随 Git 分发。文档中的相关链接
用于定位本地证据；新环境需要恢复数据、运行产物或安装引擎才能访问。
