# SnowWindow 仓库规范化与实验复现实施计划

历史计划说明（2026-10-28）：下文保留最初范围。后续用户要求三模型统一使用
G2F `full_year` 天气、2024 相关实验止于 11 月 10 日、不再读取外部天气缓存，
因此原天气缓存兼容任务已被替代；当前流程以[上手指南](../../getting-started.md)
和[配置指南](../../configuration.md)为准。用户随后明确要求整理本地改动提交，
授权本次本地提交，仍不推送；不改原始数据、历史产物或科学指标定义。

## 目标与约束

保留现有源码、全部实验配置和未提交成果，整理为轻量可复现实验仓库。
不改科学算法、选参方法或指标定义；不修改原始数据或历史产物；不自动提交、
推送或指定许可证。数据、输出、虚拟环境和第三方引擎只保留在本地。
推荐 Python 3.10，保留 `>=3.10,<3.13` 声明。不添加托管平台 CI。

## Task 1: 仓库边界与安装入口

- 根目录限定数据/输出忽略规则，排除缓存、构建目录和本地引擎源码。
- NumPy 锁定 1.26.4，统一 pytest 范围，锁定 Ruff，移除重复依赖。
- 添加 Makefile：环境准备、安装、检查、测试、集成测试与实验命令。
- 用依赖解析、独立环境安装、配置加载和忽略边界检查验收。

## Task 2: 复现兼容修复

- 先为天气缓存新旧布局、缺失来源和配置快照编写并运行失败测试。
- 优先完整的迁移后缓存布局，兼容完整旧布局，不混拼 CSV 与来源记录。
- 保存可加载配置快照，拒绝同 ID 下不同配置覆盖；audit/catalog 不创建快照。
- catalog 使用配置输出目录；保留 CLI/YAML 接口与独立 forecast 命令。
- 普通 APSIM 测试使用自建输入，真实数据/引擎测试独立执行。
- 检验重复运行、配置冲突不写产物、临时目录链路及完整回归测试。
